Тестовое задание для AQA стажёра в компании учи

Подготовка к работе
-------------------

Для начала работы убедитесь, что у вас установлены [node.js + npm](https://nodejs.org/en/download)

Установите зависимости проекта, выполнив команду:
```shell
npm ci
```

Запуск тестов
-------------

Запустите тесты с помощью команды:
```shell
npx playwright test
```

Что исправлено
--------------

**`has correct title` – падал с `TypeError: Cannot read properties of undefined (reading 'click')`**

`getPopularArticles()` возвращал `locator.all()`. Этот метод не ждёт появления элементов: если список статей
ещё не успел отрисоваться, возвращается пустой массив и `articles[0]` – `undefined`. Теперь метод возвращает
локатор, а в тесте используется `.first().click()` с автоожиданием.

**Селектор кнопки «Написать нам»**

`[class^=btn]` находит 12 элементов, причём первыми идут кнопки оценки статьи («палец вверх/вниз»), а не нужная кнопка.
Даже после исправления ожидания тест упал бы с strict mode violation. Заменил на
`[data-test=button_feedback_form]` – атрибут есть в разметке и не зависит от хешей CSS-модулей.

**Проверка заголовка**

`expect(await getTitle()).toEqual(...)` читает `textContent` один раз, сразу после клика, когда в шапке
ещё может быть заголовок предыдущего экрана. Переделал на web-first assertion
`await expect(locator).toHaveText(...)`, которое переповторяет проверку до таймаута.

**Мелочи**

- `getWidgetBody()` искал по всей странице, теперь ищет внутри виджета, как и остальные методы.
- Cookie-плашка рендерится на странице дважды (два элемента `._UCHI_COOKIE__button`). `page.click()` молча
  кликал по первому, заменил на явный `locator(...).first()`.
- Убраны неиспользуемые `page` в параметрах тестов и лишний пробел в названии `describe`.
- Добавлен скрипт `npm test`.

Дополнительный тест
-------------------

`search shows found articles` – поиск по базе знаний: вводим «пароль», проверяем, что результаты появились
и что число в заголовке «Нашлось N статей» совпадает с количеством статей в списке. Проверка не завязана
на конкретные тексты статей, поэтому не сломается при обновлении базы знаний.

Про нестабильность
------------------

Во время прогонов виджет периодически вообще не появляется на странице. Причина на стороне сервера:
запрос `https://help.uchi.ru/widget` иногда возвращается с заголовком
`Access-Control-Allow-Origin: *, https://uchi.ru` (два значения), браузер блокирует такой ответ по CORS,
и скрипт виджета не инициализируется. В удачных ответах заголовок один – `https://uchi.ru`.

Тестами это исправлять неправильно (подмена ответа через `page.route` скрыла бы реальный дефект), поэтому
в конфиг добавлено `retries: 2`, а trace на повторе уже был включён – по нему видно, что упало именно из-за
загрузки виджета. Кроме того, при частых запусках с одного IP сайт может отдать 403 «подозрительная активность».
